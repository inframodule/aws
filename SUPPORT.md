# Support Policy

## Community support

Community support is available through GitHub issues on a best-effort basis. The public repository does not include a response-time or resolution-time commitment.

Before opening an issue:

1. Use the latest supported module release.
2. Run `terraform fmt`, `terraform validate`, and the relevant module tests.
3. Review the module README, examples, and known open issues.
4. Remove credentials, account identifiers, state contents, internal hostnames, and customer information.

Include the module version, Terraform version, AWS provider version, expected behavior, actual behavior, and a minimal reproducible configuration.

## Security reports

Do not report vulnerabilities publicly. Follow [SECURITY.md](SECURITY.md).

## Commercial support

Commercial offerings may include:

- Architecture and implementation.
- Module and provider upgrades.
- Private solution blueprints.
- Security and cost reviews.
- Drift and deployment troubleshooting.
- Backup and recovery validation.
- Training and operational handoff.
- Managed infrastructure support with contractual service levels.

Until a dedicated commercial contact channel is published, open a GitHub issue containing only a high-level request for contact and no confidential information.

## Exclusions

Public community support does not guarantee:

- Compatibility with unlisted Terraform or provider versions.
- Debugging of complete customer environments.
- Access to customer AWS accounts.
- Incident response or emergency remediation.
- Legal, compliance, tax, or financial advice.
- A particular response or resolution time.
